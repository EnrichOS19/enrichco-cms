EnrichCo Salon CMS

Support team user guide · Updated April 15, 2026

What is this?

The Salon CMS at cms.enrichco.us is where you edit every salon website. Type your change, wait 2 seconds — it saves. Click Preview to see it on a test URL. Click Go Live to push it to real customers.

1. Signing in

You sign in with your IMS Next email and password (the same one that works at imsnext.enrichco.us).

  1. Open https://cms.enrichco.us in your browser.
  2. Type your email and password. Click Continue.
  3. We email you a 6-digit code. Open your inbox, copy the code, paste it in.
  4. Before clicking Verify & Sign In, choose:
    • Keep me logged in for 30 days — stay signed in on this computer for a month. Uncheck on shared computers.
    • Trust this browser — skip code next time — for 90 days, this browser won't ask for a code. Only check on your own work computer.
  5. Click Verify & Sign In. You're in.
Never check "Trust this browser" on a shared or public computer. Anyone who uses that browser can sign in as you with just the password for 90 days.

If the code doesn't arrive

  1. Check your spam folder. Emails come from noreply@enrichco.us.
  2. Codes expire in 5 minutes. If it's been longer, click ← Use a different account, sign in again to get a fresh code.
  3. Still nothing? Ping Webber.

If login fails

The CMS shows the exact error from IMS Next. Common ones:

  • "Invalid credentials" — wrong email or password. Try logging into imsnext.enrichco.us directly to check which is wrong.
  • "Password must be at least 6 characters" — your IMS password is too short. Reset it in IMS Next first.
  • "Unable to reach authentication server" — IMS Next is down. Wait a minute, try again. If it keeps failing, ping Webber.
Your CMS login uses IMS Next only. If you've only ever used the old IMS at ims.enrichco.us, you may not have an IMS Next account yet. Ask Sean or Webber to set one up.

There is no "Forgot password" link in the CMS. To reset your password, use imsnext.enrichco.us and come right back.

2. The dashboard

After signing in, you land on the salon list. Every salon we manage is here.

What each card shows

  • Name of the salon, and its city + state.
  • Status badge (right side of the card):
    • Approved — has services, gallery photos, brand colors, and a real booking URL. Ready for customers.
    • Demo Ready — has services, gallery, brand colors — but still needs a booking URL.
    • New — missing services, gallery, or branding. Not ready yet.
  • Count of services and gallery photos.
  • Phone number, if set.

Finding a salon

  1. Type in the search box — it matches name, city, or state.
  2. Or click a filter tab: All, Approved, Demo Ready, New.
  3. Click the salon's card to open its editor.

Top bar

  • Your email (shows you're signed in).
  • Admin link — only visible to super admin.
  • Sign out — ends your session on this computer.

3. The salon editor

Click any salon on the dashboard. You land on its editor, which has three parts:

  1. Left sidebar (desktop) or top bar (mobile) — salon name, current domain, status badge, and 9 tabs.
  2. Main area — the tab you're on, with all its editable fields.
  3. Bottom bar — save status (left) and Preview / Go Live buttons (right).

Status badge in sidebar

BadgeMeaning
ProductionThis salon is live. Go Live will push to real customers.
StagingThis salon is not launched yet. Go Live needs a Production domain configured in Settings first.
UnsavedYou have changes that haven't been autosaved yet (usually appears for a second or two).

The domain link

Below the salon name in the sidebar, there's a clickable link with the salon's domain. Click it to open the live or staging site in a new tab.

4. How saving works

There is no "Save" button. The CMS saves automatically about 2 seconds after you stop typing.

Save status (bottom bar)

You seeMeans
Editing...You just typed something. Save is about to fire.
Saving...Writing to the server right now.
All changes savedSafe to close the tab.
Save failed — click to retrySomething went wrong. Click the message to try again.

Force a save right now

Hit Cmd+S (Mac) or Ctrl+S (Windows). It saves immediately without waiting for the 2-second debounce.

Leaving the page with unsaved changes? The browser warns you. Wait for "All changes saved" before closing.

If you see "Fix validation errors before saving"

A field has bad data (for example, an empty required field). Scroll to find the red error message, fix the field, and it'll save. The red banner disappears on successful save.

5. Previewing changes

Preview lets you see your edits on a real test URL before pushing to customers. Use it every time before Go Live.

  1. Make your changes. Wait for All changes saved in the bottom bar.
  2. Click Preview in the bottom-right.
  3. A new browser tab opens with the staging URL (for example happy-nails-spa.pages.dev).
  4. The CMS builds the updated site in the background — takes 30 to 60 seconds. You'll see a toast say "Staging updated with your changes" when it's done.
  5. Reload the preview tab to see your edits.
Browser blocked the popup? Allow popups for cms.enrichco.us. The CMS only ever opens the staging URL — nothing else.
No staging domain configured? You'll see an error: "No staging domain configured. Set one in Settings." Open the Settings tab and fill in Staging Domain, then try again.

6. Going live (pushing to production)

Go Live pushes your changes to the real customer-facing site. Customers see it within a minute.

  1. Always preview first. Make sure staging looks right.
  2. Click Go Live in the bottom-right.
  3. A dialog pops up: "Go Live?" with the production domain in bold (e.g. happynailandspa.com).
  4. Read the domain carefully. If it's correct, click Go Live. If it's wrong or you're not ready, click Cancel.
  5. Wait for the toast to say "Live site updated!". That's it — customers see your changes on the next page reload.
Go Live is not reversible from the CMS UI. If you push something wrong, you have to either fix it and Go Live again, or ask Webber to run a rollback. Preview first.
The Go Live button is disabled if:
  • Your last save failed — fix validation errors first.
  • A Preview build is still running — wait for it to finish.
  • You're a Support user — only Admin and Super Admin can Go Live.

7. Each tab explained

Every salon has the same 9 tabs in the sidebar. Here's what's in each.

Info

Basic salon details and contact info.

  • Salon Name and Tagline
  • Description (paragraph)
  • Logo — upload the salon's logo (JPG, PNG, WebP, or SVG, max 5MB). It shows in the header, footer, and browser tab on the live site. Click Replace Logo to upload a new one. Preview or Go Live to publish it.
  • Phone and Email
  • Address: Street, City, State, ZIP (separate fields — the live site combines them)

Hours

Set your business hours for each day.

One row per weekday. Type open and close times in plain English (for example 9:30 AM or 7:00 PM). Leave both blank for a closed day.

Starting from scratch?

If the hours list is empty, click + Add Default Schedule. It fills in:

  • Monday–Saturday: 9:30 AM to 7:00 PM
  • Sunday: 11:00 AM to 5:00 PM

Edit any row after. Use the trash icon to remove a day. Use + Add Day to add more.

Services

Manage service categories and pricing.

Services are grouped into categories. For each service:

  • Name — what it's called (e.g. Classic Manicure)
  • Description — optional details (keep it short)
  • Price — any format: $45, 45, from $30, $25–$40

Common edits

  1. Add a category: Click + Add Category, click the "New Category" text to rename it.
  2. Add a service: Click + Add Service inside a category. Fill in name, price, optional description.
  3. Reorder services: Use the up/down arrows on the left side of each service row. The order in CMS = the order on the live site.
  4. Reorder categories: Use the up/down arrows next to the category name. Categories appear on the site in the same order.
  5. Delete a service: Click the trash icon next to it. Confirm.
  6. Delete a category: Click the trash icon next to the category name. This deletes all services in it.
Order matters. The live website shows services and categories in the exact same order as the CMS. Move items up/down to control what customers see first. Click Preview after reordering to verify.

Gallery

Manage gallery photos.

Add a photo

  1. Click + Add Image to add a blank row.
  2. Either click Choose File in the row to upload (JPG, PNG, or WebP, up to 5 MB)
  3. Or paste a full image URL into the first text box.
  4. Type an Alt text description (helps accessibility and SEO).

Reorder or remove

  • Up / down arrows change the order.
  • Trash icon removes the image from the gallery.
Photo not loading? Some older galleries use Unsplash URLs that expire. If a photo shows as empty, re-upload it or paste a fresh URL.

Design

Colors, fonts, and template selection.

Brand Colors

Nine color fields, each with a color picker and a hex input. Pick with the swatch or type a hex like #6366f1.

  • Primary, Accent, Background — the three colors most templates use.
  • Primary Light, Primary Dark, Surface, Surface Light, Text, Text Muted — fine-tune the look.

Typography

  • Heading Font — e.g. Playfair Display
  • Body Font — e.g. Inter

Preview

A live preview box shows the salon name, tagline, and Primary/Accent color swatches using your current settings. Updates as you type.

Design Template

Below the preview, the Template Switcher lets you change the entire site layout. Your content is always preserved — only the visual design changes. Templates are built by Webber; ask before switching.

About

Tell visitors about your salon. Four paragraphs shown on the About page:

  • Welcome Message — a warm intro at the top of About.
  • Our Mission — what the salon stands for.
  • Sanitation & Safety — health and cleanliness practices.
  • Our Values — list format. Put one value per line (for example: Quality craftsmanship → Enter → Customer satisfaction → Enter → Cleanliness).

Blog

Create and manage blog posts.

Two views

  • List view — cards for every post with thumbnail, title, date, category, and excerpt. Hover shows edit and delete buttons. Click a card to open it.
  • Edit view — full post editor. Click ← Back to all posts to return to the list.

Add a new post

  1. Click + New Post in the top-right of the list.
  2. Fill in Title. The URL slug auto-generates from the title.
  3. Set Date, Category (e.g. Nail Care), and Read Time (e.g. 5 min read).
  4. Paste a Featured Image URL (full URL starting with https://).
  5. Write an Excerpt — a 1-2 sentence summary shown on the blog listing.
  6. Write the Content in HTML. A live Preview shows how it renders.
  7. Autosave handles the rest. Click ← Done editing to return to the list.

Delete a post

  • From the list: hover the card, click the trash icon, confirm.
  • From edit view: click Delete Post at the bottom right.
Content must be HTML. Use <p>paragraph</p>, <h2>heading</h2>, <ul><li>item</li></ul>. If you just type plain text, it all runs together.

SEO

Search engine optimization and social sharing.

  • Page Title — what shows in browser tabs and Google results. Aim for 50–60 characters.
  • Meta Description — Google's search snippet. The editor shows "X / 160 characters" — stay under 160.
  • Keywords — comma-separated. Minor ranking impact today but still used by some indexes.
  • Social Share Image URL — the image shown when someone shares the site on Facebook or iMessage. Must be a full URL (https://...).
  • Canonical URL — the preferred URL for this site, usually the production domain.
The Social Share Image must be a full URL. Relative paths like /images/photo.jpg won't load on Facebook or iMessage.

Settings

Booking URL and social media links. Also where you set domains and production status.

Booking

  • Booking URL — where the "Book Now" button sends customers. Usually the salon's Mango POS booking page.

Publishing

  • Site Status — dropdown with two choices:
    • Staging — site is under construction — Go Live is disabled for this salon.
    • Production — site is live — Go Live is enabled.
  • Staging Domain — the preview URL. Example: nailsalon12.mangotemplates.us or happy-nails-spa.pages.dev.
  • Production Domain — the real customer domain. Example: happynailandspa.com.
Before switching to "Production", make sure the production domain's DNS actually points to our server (34.138.245.90). If DNS is still parked or pointing somewhere else, Go Live will succeed but customers will see a different site. Ask Vision or Webber if unsure.

Ownership & Management

Two dropdowns that tell everyone who controls what:

  • Domain Ownership — EnrichCo (we own the domain in GoDaddy) or Client (the salon owns it).
  • Website Manager — AI Team (managed via this CMS, Next.js) or Marketing Team (managed via FTP, PHP templates).

These show as colored badges on the dashboard cards so you can see at a glance.

Social Links

Full URLs for each platform — these show up in the footer of the live site:

  • Instagram
  • Facebook
  • Google (Google Business listing)
  • Yelp

Leave blank if the salon doesn't use that platform — the icon won't appear on the live site.

9. Troubleshooting

"Save failed — click to retry"

  1. Click the red message. It retries the save.
  2. If it keeps failing, you probably have a validation error. Scroll the tab you're on for red text and fix it.
  3. Still failing? Ping Webber with the salon name and what you were editing.

"Fix validation errors before saving" banner

Some field has bad data (empty required field, invalid phone, invalid URL). Scroll until you find a red message under a field, fix it, and save works again.

"Publish failed" after Go Live

Rare. Check that Production Domain in Settings is a real domain like something.com. If it is, ping Webber with the salon name and the error message.

Preview shows the old content

  1. The background build takes 30–60 seconds. Reload the preview tab after that.
  2. If it still looks old after a minute, hard-reload: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows).

Gallery photo shows empty

Older Unsplash URLs expire. Re-upload the photo from your computer, or paste a fresh URL.

Can't sign in — no OTP email

  1. Check spam. Sender is noreply@enrichco.us.
  2. Try signing in again to get a new code (old codes expire in 5 minutes).
  3. If it still doesn't arrive, your email may not have an IMS Next account. Ask Sean or Webber.

10. Agent template workflow

This section is for AI agents (Webber and team) — not human operators. It explains how to read and write shared template components without breaking CMS state.

The three-copy problem

Every managed salon website exists in three places at once:

  1. Mac source — /Users/aisquad/salon-websites/sites/<slug>/
  2. Server source — /opt/enrich-cms/sites/<slug>/
  3. Live web root — /var/www/<domain>/public/

Shared components (Navigation, Footer, etc.) live in one canonical location: /opt/enrich-cms/template/components/ on the server and /Users/aisquad/salon-websites/template/components/ locally. They are injected at build time — never committed into individual site source.

Reading a shared component

GET /api/template/components/<filename> — requires any authenticated session. Returns:

{
  "filename": "Navigation.tsx",
  "content": "...",
  "sha256": "abc123..."
}

Always save the sha256 — you need it to write back.

Patching a shared component (safe, atomic)

Use POST /api/template/batch-patch — requires Super Admin. Supply the SHA you got from the read (compare-and-swap guard prevents blind overwrites):

POST /api/template/batch-patch
{
  "file": "Navigation.tsx",
  "expected_sha256": "<sha from GET>",
  "patches": [
    { "old": "h-10 w-auto", "new": "h-14 w-auto" }
  ]
}

The server rejects the write with HTTP 409 if the file changed since you read it, and HTTP 422 if any patch string matched zero times. A backup (.bak) is created before every write.

Rebuilding sites after a template change

After changing a shared component, trigger a batch rebuild so all affected sites pick up the change:

POST /api/template/rebuild-all
{ "dryRun": false }          // omit slugs to rebuild all production sites
// or
{ "slugs": ["happy-nails", "pino-nails"], "dryRun": true }  // subset + dry run

The route returns a jobId immediately. Poll status at:

GET /api/template/rebuild-all?jobId=<id>

The job runs sequentially (one site at a time), respects per-slug publish locks, and writes progress to /tmp/rebuild-job-<id>.json.

Agent workflow summary

  1. Read the component file → save SHA
  2. Apply patches via batch-patch with that SHA
  3. Start a rebuild-all job (or target specific slugs)
  4. Poll until done: true — check failed count
  5. Log the new SHA in the audit trail (done automatically)

Never write directly to site source files to change shared components. That creates drift between Mac source and server source. Always use the template API.
